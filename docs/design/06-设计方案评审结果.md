## 1. 评审结论

本轮评审覆盖功能完整性、架构合理性、数据库与接口一致性、规范与约束四个方面。

总体结论：**设计方向一致，核心链路完整，可以作为实施基线。**

- 用户、认证、RBAC、菜单、系统参数、审计日志、公开 API 均有对应模块、表结构与接口。
- 单体多模块边界清晰，业务模块零直接依赖，跨模块通过端口与事件契约协作，未发现循环依赖。
- 数据库与 API 的主体字段一致；未发现物理外键。
- 规范检查发现的问题以索引命名、索引选择、DTO 定义、PUT 空值语义、规则文档示例不一致为主，均已在文档中修正。
- 本轮评审新增的资源/参数生命周期、资源停用子资源、仪表盘菜单、`SUPER_ADMIN` 禁用、`API` 类型定位事项已全部确认，详见第 8 节。结论为：**资源与参数由 Flyway 迁移维护；停用资源需无启用子资源；移除仪表盘；`SUPER_ADMIN` 不可禁用；`API` 为预留类型。**

限制说明：仓库内未发现独立的页面原型文件，本次评审以 01 文档的功能描述、03 文档的核心资源树和 05 文档的页面范围为依据。

## 4. 架构合理性检查

### 4.1 模块与依赖

- 9 个 Maven 模块的职责划分与 01 的功能范围一致。
- 依赖矩阵无环：`common-*` 不依赖业务模块，业务模块之间零直接依赖，`bootstrap` 只做装配。
- `CurrentUserProvider`、`PermissionProvider`、`ConfigProvider`、日志事件与 `@OperationLog` 契约的归属方和使用方清晰。
- ArchUnit 规则覆盖了模块依赖、分层方向、`common-core` 技术依赖等关键边界。

### 4.2 认证与授权

- opaque token + Redis 哈希存储 + 设备级单会话 + 滑动/绝对过期，与 01 的会话要求一致。
- Web Cookie 与 App Bearer 双模式、CSRF 跳过规则、强制下线语义完整。
- 权限缓存按用户缓存，角色/资源/用户状态变化时失效，与 01 的即时生效要求一致。

### 4.3 已修正的架构表述问题

- 02 中登录 `device` 的取值原为小写 `web` / `app` / `mini`，与 03/04 的 `WEB` / `APP` / `MINI` 不一致；已统一为大写，并补充 `device → loginType` 的派生规则。
- 02 未明确登录日志与操作日志的消费时序；已补充：登录日志同步消费，操作日志在事务提交后异步消费。

### 4.4 非阻塞观察

- `bootstrap` “新增业务模块只增加一行 Maven 依赖”是目标而非绝对约束；MyBatis-Plus Mapper 扫描、Flyway 多 jar 扫描可能仍需配置。建议在 Phase 1A 验证，不作为设计缺陷。
- `keel-iam` 内部按身份、认证、授权划分子域，ArchUnit 规则 8 已约束子域边界，方向合理。
- 02 §3.5 保留了 `DataScopeProvider` 占位，但 01 明确本期不做数据权限；如无近期计划，建议删除或标注为未启用，避免过早抽象。本轮未改动，列为非阻塞观察。

## 8. 评审确认结论

以下事项已完成交互确认，作为设计定稿依据。保留原候选方案用于记录决策背景。

### P-01 资源删除接口是否提供

**确认结论**：选择 A。不提供后台删除；资源新增/删除由 Flyway 迁移维护，删除保护规则在迁移评审与完整性检查中执行。

**评审时现状**：01 §4.3 要求“资源有子节点或被授权时禁止删除”，03 §7.2 定义了资源删除规则，但 04 没有 `DELETE /iam/resources/{id}`；04 只提供更新展示属性与启停。

**影响**：如果不提供删除接口，资源生命周期完全由 Flyway 迁移管理；03 §7.2 的删除规则只能在迁移/运维层面执行。如果提供删除接口，还需要同时明确资源创建方式，否则只能删除种子资源。

**候选方案**：

- A（推荐）：v1 不提供后台删除；资源新增/删除统一走“前端发版 + Flyway 迁移”，03 明确删除校验由迁移评审和完整性检查承担。
- B：新增 `DELETE /api/v1/admin/iam/resources/{id}`，并补充 `IAM_RESOURCE_IN_USE` / `IAM_RESOURCE_PROTECTED` 错误码；同时需要定义资源创建方式。

### P-02 系统参数删除接口是否提供

**确认结论**：选择 A。不提供后台删除；参数新增/删除由 Flyway 迁移或运维执行，后台只更新参数值。

**评审时现状**：01 §2.2 提到“菜单/配置硬删除”，03 §7.2 写明“系统参数允许硬删除”，但 04 只有查询与更新，没有删除或新增接口。

**影响**：如果参数只由 Flyway 种子维护，管理员只需要更新值；如果需要运行时增删参数，应补齐 `POST` / `DELETE` 接口与操作日志规则。

**候选方案**：

- A（推荐）：v1 参数集合由迁移维护，后台只允许更新；03 明确“硬删除仅通过迁移/运维执行”。
- B：新增参数创建与删除接口，并补充唯一键冲突、公开标记限制与操作日志规则。

### P-03 仪表盘菜单是否保留

**确认结论**：选择 A。从种子中移除仪表盘菜单；Admin 登录后跳转第一个有权限菜单。

**评审时现状**：03 §9.2 种子包含 `dashboard:view`（MENU，路径 `/dashboard`，组件 `dashboard/index`），但 01 未定义仪表盘功能，04 没有对应 API，05 的 Admin 页面清单也未包含仪表盘。该 code 为两段式，与“权限码 `模块:资源:动作`”不完全一致。

**影响**：保留会引入需求文档未定义的功能；删除后 Admin 需要一个默认落地页（可重定向到第一个有权限的菜单）。

**候选方案**：

- A（推荐）：从种子中移除仪表盘菜单，Admin 登录后重定向到第一个有权限的菜单。
- B：保留为纯前端壳页面，将 code 改为 `dashboard:overview:view`，并在 01 补充“仪表盘壳页面”范围。
- C：保留现状，在 01/03 中明确两段式菜单 code 的例外。

### P-04 `SUPER_ADMIN` 是否允许禁用

**确认结论**：选择 A。不允许禁用，并同步到 01 §4.3、02 §4.5、03 §5.2、04 §6.4。

**评审时现状**：01 §4.3 只规定 `SUPER_ADMIN` 不可删除、不可修改 code；04 §6.4 增加了“`SUPER_ADMIN` 不允许禁用”，03 的种子默认启用。

**影响**：不允许禁用更安全，但这是 01 未写明的业务规则；允许禁用则可能导致系统失去超级管理员入口。

**候选方案**：

- A（推荐）：确认“不允许禁用”，并补充到 01 §4.3、03 §5.2，使 01/03/04 一致。
- B：从 04 移除该限制，允许禁用，但需定义禁用后的兜底恢复流程。

### P-05 `API` 资源类型的定位

**确认结论**：选择 A。`API` 作为预留类型，当前不种子化；接口鉴权复用 `MENU` / `BUTTON` 的权限码。

**评审时现状**：01 §4.3 和 03 §5.3 将 `API` 列为资源类型，但 03 §9.2 的种子资源没有 `API` 类型；04 的接口权限复用了 `MENU` / `BUTTON` 的 code。

**影响**：当前实现可以工作，但 `API` 类型处于“有定义、无数据”的状态，容易让实现者误解。

**候选方案**：

- A（推荐）：明确 `API` 为预留类型，用于未来“无 UI 的纯接口权限”；当前不种子化，接口鉴权继续复用 MENU/BUTTON code。在 03 §5.3 增加说明。
- B：为需要独立授权的接口种子化 `API` 资源，并调整 04 的权限码映射；会增加重复授权关系，不建议在 v1 引入。

### P-06 资源/参数的运行时创建是否在范围内

**确认结论**：选择 A。不提供运行时创建；资源与参数统一由 Flyway 迁移维护。

**评审时现状**：01 §4.4 规定“新增页面必须前端发版 + 新增迁移”，04 没有资源创建接口；系统参数也只有更新接口。

**影响**：这决定 P-01/P-02 的最终方案，也决定 Admin 是否需要“新增资源/新增参数”页面。

**候选方案**：

- A（推荐）：v1 统一为“迁移维护资源与参数，后台只改展示属性/参数值”；不新增创建接口。
- B：开放运行时创建，需要补齐创建接口、权限码、静态路由校验和操作日志规则。

### P-07 资源停用时如何处理启用子资源

**确认结论**：选择 A。停用目录/菜单前校验启用子资源；存在则返回 409 `IAM_RESOURCE_HAS_ENABLED_CHILDREN`。

**评审时现状**：04 §7.4 允许对任意资源启停，但未定义停用目录/菜单时其启用子菜单、按钮、接口资源的处理方式。

**影响**：可能出现子资源仍被授权、但父节点不可见的情况，导致菜单树、按钮权限与接口鉴权不一致。

**候选方案**：

- A（推荐）：停用资源前校验启用子资源，存在则返回 409，由管理员先处理子资源；与删除保护规则一致。
- B：级联停用所有子资源，并在操作日志中记录影响范围。
- C：允许停用，但在权限计算与菜单树构建时忽略父级停用的整棵子树；需要明确遍历规则。
