# 05 实施计划与工程规范

> 状态：v0.3（评审确认同步）
> 更新：2026-11-12
> 关联：`01-需求与功能模块梳理.md`、`02-技术选型与整体架构.md`、`03-数据库设计.md`、`04-API接口设计.md`、`06-设计方案评审结果.md`、`../rules/database-rules.md`、`../rules/api-rules.md`

## 1. 实施原则

1. **先设计、后编码**：未经明确授权，不提前编写或修改业务代码。
2. **Walking Skeleton**：先打通最小端到端竖切，再横向扩展。
3. **小步验收**：每个任务可独立验收，不跨阶段堆积。
4. **验证门**：Phase 1A 的兼容性验证不通过，不进入功能开发。
5. **文档同步**：数据库、API、模块职责或核心流程变更时，同步更新 01–04 与规则文档。
6. **最小改动**：不引入需求未定义的业务功能；必要补充先提出建议。

### 1.1 完成定义（Definition of Done）

一个任务完成必须同时满足：

- 功能按验收标准可用。
- 相关测试通过；高风险逻辑有定向测试。
- 数据库迁移可重复执行，且在 Testcontainers 上通过。
- API 变更已更新 `04-API接口设计.md` 与 OpenAPI 快照。
- 架构约束（ArchUnit）通过。
- 受影响的文档已同步。
- 没有越界修改其他模块。

## 2. 环境与仓库

### 2.1 工具链

| 工具 | 要求 |
|---|---|
| JDK | 25 LTS |
| Maven | 3.9+，由开发环境与 CI 预装；不提交 Maven Wrapper |
| Node.js | LTS，使用 `.nvmrc` 固定主版本 |
| pnpm | 每个前端仓库独立锁文件 |
| Docker | 本地集成测试、Testcontainers、Compose |
| MySQL | 8.x |
| Redis | 由部署环境提供 |

### 2.2 目录与仓库

当前采用单仓库多工程结构，各工程位于独立子目录，依赖与构建产物互相隔离：

| 目录 | 内容 |
|---|---|
| `backend/` | 后端：Maven 多模块，模块名保留 `keel-*`；文档与规则位于仓库根 |
| `frontend/admin/` | 管理端：Vue 3 + TypeScript + Vite + shadcn-vue |
| `frontend/portal/` | 门户：Vue 3 + TypeScript + Vite + Tailwind |
| `deploy/` | 部署资源：Docker Compose、环境变量模板与后续 Nginx 配置 |

各工程独立安装依赖、独立构建与部署；API 契约通过 OpenAPI 快照同步。后续需要独立 CI、独立版本发布时，可将 `frontend/admin/` 与 `frontend/portal/` 拆分为独立仓库。

后端坐标：groupId `io.github.keel`，artifactId 前缀 `keel-`，版本 `1.0.0`，包根 `io.github.keel`。

### 2.3 配置

- 后端使用 Spring Profile：`local`、`test`、`prod`。
- 敏感配置通过环境变量注入，不提交到仓库。
- 前端使用 `.env.local` / `.env.production`；只允许公开配置，禁止放密钥。
- 时区统一：`TZ=Asia/Shanghai`、`-Duser.timezone=Asia/Shanghai`。

## 3. 阶段计划

### Phase 1A：技术底座验证

**目标**：在不扩展业务的前提下，验证技术栈与工程骨架。

**范围**

- 根 POM、9 个模块骨架、BOM。
- MyBatis-Plus 一次 CRUD 与分页。
- Flyway 加载 `iam` 与 `system` 两个模块的迁移。
- SpringDoc 分组文档。
- Testcontainers 启动 MySQL / Redis。
- Spring Security 无状态 token 过滤器，跑通 Cookie 与 Bearer。
- Admin 仓库 shadcn-vue + Tailwind v4 初始化并构建。
- ArchUnit 基础规则。

**验收门**

- [ ] `mvn verify` 通过。
- [ ] 应用上下文启动成功。
- [ ] 两个模块迁移按序执行。
- [ ] `/v3/api-docs` 可访问。
- [ ] Testcontainers 集成测试通过。
- [ ] 登录 → token → `/me` 链路可用。
- [ ] Admin `pnpm build` 成功。
- [ ] `/actuator/health` 可访问，其他 Actuator 端点未暴露。
- [ ] ArchUnit 规则通过。

任一项失败：暂停扩展，调整版本或执行回退方案。

### Phase 1B：最小竖切

**目标**：打通登录、当前用户、用户列表的前后端闭环。

**范围**

- 后端：登录、登出、`/me`、CSRF、用户分页。
- 前端：登录页、基础布局、用户列表、401 跳转。
- OpenAPI 导出与 TypeScript 类型生成。
- Playwright：登录与用户列表关键路径。

**验收**

- [ ] Web 登录成功并写入 Cookie。
- [ ] App 模式返回 Bearer token。
- [ ] 未登录返回 401，前端跳转登录页。
- [ ] 用户列表分页正常。
- [ ] 登录失败记录登录日志。
- [ ] Playwright 用例通过。

### Phase 2：RBAC

**范围**

- 角色、资源、角色-资源、用户-角色。
- 资源由 Flyway 迁移维护；后台只更新展示属性与启停状态。
- `SUPER_ADMIN` 绕过、权限缓存、菜单树。
- 用户禁用、强制下线、密码重置。
- Admin：角色/资源页面、权限指令、后端菜单驱动侧边栏；无仪表盘、无资源新增/删除入口。
- Playwright：403、角色授权、菜单可见性。

**验收**

- [ ] 角色授权变更后下一次请求生效。
- [ ] 普通管理员只能看到被授权菜单与按钮。
- [ ] 超级管理员可访问全部功能。
- [ ] 强制下线后目标 token 立即失效。
- [ ] 停用存在启用子资源的目录/菜单返回 409。
- [ ] 角色删除保护生效；资源删除保护由迁移评审执行。

### Phase 3：系统参数与审计日志

**范围**

- 系统参数查询与更新、公开参数接口；参数由迁移维护，无运行时新增/删除。
- 操作日志异步写入、登录日志同步写入。
- 日志查询、保留期清理任务。
- Admin：参数页、操作日志页、登录日志页；参数页无新增/删除入口。

**验收**

- [ ] 参数修改后按约定刷新。
- [ ] 参数新增/删除仅通过迁移执行。
- [ ] 事务回滚不产生操作日志。
- [ ] 登录失败记录原因。
- [ ] 清理任务按保留期分批删除。
- [ ] 日志中无敏感信息。

### Phase 4：Portal

**范围**

- Portal 仓库初始化。
- 公开配置接口对接、首页骨架。
- 同域部署验证。

**验收**

- [ ] 未登录可访问公开接口。
- [ ] 公开接口不能访问管理端数据。
- [ ] Portal 构建与部署成功。

### Phase 5：加固与交付

**范围**

- ArchUnit 规则补全。
- Playwright 覆盖关键流程。
- Docker Compose、Nginx 配置、README、AGENTS.md。
- 文档与实现一致性检查。

**验收**

- [ ] 全量构建通过。
- [ ] 关键 E2E 通过。
- [ ] 同域 `/admin`、`/portal`、`/api/v1` 可用。
- [ ] 文档、规则、OpenAPI 快照同步。
- [ ] 交付清单完成。

## 4. 后端实施顺序

### 4.1 模块顺序

1. 根 POM / BOM。
2. `common-core`。
3. `common-web`。
4. `common-persistence`。
5. `common-security`。
6. `bootstrap` 骨架。
7. `iam`：用户、角色、资源、认证、授权。
8. `system`：系统参数。
9. `audit`：操作日志、登录日志。
10. ArchUnit 规则与集成测试。

### 4.2 任务粒度

每个任务应满足：

- 一个明确目标，可在一次评审中看完。
- 有可执行的验收标准。
- 有定向测试或验证方式。
- 不修改任务范围外的模块。

示例任务拆分：

- 建立 `iam_user` 表与 Flyway 迁移。
- 实现用户分页查询与详情接口。
- 实现创建用户与用户名唯一校验。
- 实现登录与 token 过滤器。
- 实现权限缓存与 `/me` 菜单树。
- 实现操作日志异步写入。

### 4.3 关键集成点

| 集成点 | 约束 |
|---|---|
| `common-security` ↔ `iam` | 通过 `PermissionProvider` 端口反向依赖 |
| `common-persistence` ↔ `common-core` | 通过 `CurrentUserProvider` 获取审计操作人 |
| `system` ↔ 业务模块 | 通过 `ConfigProvider`，禁止直接依赖 |
| `audit` ↔ 业务模块 | 通过事件契约，禁止业务模块依赖审计实现 |
| `bootstrap` | 只装配，不写业务逻辑 |

## 5. 前端实施顺序

### 5.1 Admin

1. Vite + Vue 3 + TypeScript + pnpm 初始化。
2. Tailwind v4 + shadcn-vue 初始化（`new-york`、CSS 变量、Lucide）。
3. ESLint、Prettier、TypeScript strict、`vue-tsc`。
4. Axios 封装、CSRF、401/403。
5. Pinia auth store、路由守卫、布局。
6. 登录页、用户列表页。
7. 角色/资源/参数/日志页面。
8. Playwright 关键流程。

### 5.2 Portal

1. Vite + Vue 3 + TypeScript + Tailwind + shadcn-vue，与 Admin 保持一致。
2. 匿名 API 客户端。
3. 首页骨架与公开配置展示。
4. 独立构建与部署。

### 5.3 组件约定

- `components/ui` 为 shadcn-vue 生成组件，尽量不修改。
- 业务封装放 `components/app`：DataTable、PermissionTree、PageHeader。
- 权限树使用 Reka UI Tree 自建，不引入穿梭框。
- 记录 shadcn-vue 初始化版本与组件清单，升级时手动对比。

## 6. 测试策略

### 6.1 后端

| 类型 | 范围 | 工具 |
|---|---|---|
| 单元测试 | 领域规则、应用服务、工具函数 | JUnit 5 |
| 集成测试 | Repository、事务、Flyway、Redis | Testcontainers |
| API 测试 | Controller、校验、鉴权、错误码 | MockMvc + Testcontainers |
| 架构测试 | 模块依赖、分层、包边界 | ArchUnit |

- 集成测试使用真实 MySQL 8 与 Redis，不用 H2 替代。
- 每个阶段结束运行 `mvn verify`。
- 不设形式化覆盖率门槛，优先覆盖认证、授权、迁移、并发与错误路径。

### 6.2 前端

- CI 平台暂不绑定；以下阶段使用平台无关命令。
- 仅使用 Playwright。
- 覆盖：登录/登出、401/403、必须改密、用户 CRUD、角色授权、菜单可见性、日志查询。
- 失败时保留 trace 与 video。
- PR 执行 lint、typecheck、build；E2E 在主分支或每日构建执行。

### 6.3 测试数据

- 通过 Flyway 种子 + 测试夹具创建。
- 不使用生产数据。
- 测试用户、角色、资源使用固定 code，便于断言。

## 7. 数据库与迁移流程

1. 设计变更先更新 `03-数据库设计.md`。
2. 新增迁移文件，遵守版本段与命名规则。
3. 在 Testcontainers 上执行迁移与集成测试。
4. 迁移评审重点：锁、索引、数据量、回滚方案。
5. 已执行迁移禁止修改；修正通过新迁移完成。
6. 破坏性变更前备份，并提供回滚说明。

详细规则见 `../rules/database-rules.md`。

## 8. API 契约流程

1. 端点变更先更新 `04-API接口设计.md`。
2. 后端通过 SpringDoc 导出 `openapi.json`。
3. 前端将快照提交到各自仓库的 `openapi/openapi.json`，生成 TypeScript 类型。
4. CI 校验生成物与快照一致。
5. 破坏性变更进入 `/api/v2`；v1 只做加法。

详细规则见 `../rules/api-rules.md`。

## 9. 代码质量与规范

### 9.1 后端

- 包结构、模块依赖、分层遵守 `02` 与 ArchUnit。
- Maven Enforcer 校验 Java / Maven 版本。
- 编译开启 `-parameters`。
- 禁止跨模块直接依赖；禁止在 `common` 中写业务逻辑。
- 禁止物理外键；数据库约束与应用校验共同保证完整性。
- 高风险改动（认证、token、权限、迁移、安全配置）需要独立评审。
- 代码格式保持项目一致；格式化插件按团队偏好决定，不作为前置阻塞。

### 9.2 前端

- ESLint flat config + Prettier + TypeScript strict。
- CI 执行 `pnpm lint`、`pnpm typecheck`、`pnpm build`。
- 禁止无理由使用 `any`。
- 认证状态只放 Pinia，不写 `localStorage` token。
- 生成的 OpenAPI 类型与 `components/ui` 不手工修改。

### 9.3 文档

- 决策变更先改文档，再改代码。
- 01–04 与规则文档保持单向引用，避免重复描述。
- 代码与文档不一致视为缺陷。

## 10. 部署与运行

### 10.1 同域部署

```
https://example.com/admin      -> Admin 静态资源
https://example.com/portal     -> Portal 静态资源
https://example.com/api/v1     -> 后端
```

- Nginx 负责静态资源与反向代理；SPA 路由回退到各自 `index.html`。
- 同源部署，无 CORS；Cookie 正常工作。
- 静态资源带 hash 长缓存，`index.html` 不缓存。

### 10.2 Docker

- 后端镜像：JRE 25 + 可执行 jar。
- 前端镜像：Nginx + 构建产物，或由统一 Nginx 挂载。
- 本地 Compose 文件位于 `deploy/`：MySQL、Redis、后端、Nginx（含两个前端）。
- 容器统一 `TZ=Asia/Shanghai`，JVM 指定 `-Duser.timezone=Asia/Shanghai`。

### 10.3 环境变量

| 变量 | 说明 |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `local` / `test` / `prod` |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | MySQL 连接 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis 连接 |
| `KEEL_ADMIN_USERNAME` | 初始管理员用户名 |
| `KEEL_ADMIN_PASSWORD` | 初始管理员密码；生产必填 |
| `TZ` / `JAVA_TOOL_OPTIONS` | 时区 |
| `VITE_API_BASE_URL` | 前端构建期 API 前缀，默认 `/api/v1` |

### 10.4 健康检查与日志

- 引入 Actuator，仅暴露 `/actuator/health`；其他端点不对外暴露。
- 日志输出到 stdout，由容器平台收集。
- 日志包含 `X-Request-Id`，与前端错误提示关联。

### 10.5 备份与回滚

- 破坏性迁移前备份数据库。
- 应用回滚使用上一版本镜像；数据库只前进，不执行 undo。
- 回滚前确认旧版本代码兼容当前 schema。

## 13. 风险与回退

| 风险 | 影响 | 应对 |
|---|---|---|
| Boot 4 生态兼容性 | 依赖不可用 | Phase 1A 验证；MP 失败切原生 MyBatis，SpringDoc 降级 |
| Tailwind v4 / shadcn-vue 工具链 | 前端构建失败 | Phase 1A 验证；回退 Element Plus + SCSS |
| 无物理外键 | 孤立关联 | 应用校验 + 唯一约束 + 集成测试 |
| 本地时区 | 多地域迁移成本 | 三处时区一致；文档记录例外 |
| 静态路由与菜单漂移 | 菜单 404 | 前端启动校验；发版与迁移成对执行 |
| 仅 Playwright | 回归反馈慢 | 控制 E2E 范围；核心组件频繁改动时补 Vitest |
| 日志表增长 | 查询与存储压力 | 保留期 + 分批清理；必要时分区 |
| 多实例清理任务 | 重复执行 | 单实例不加锁；多实例前引入 ShedLock 或等价分布式锁 |
