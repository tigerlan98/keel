# 01 需求与功能模块梳理

> 状态：v0.3（需求基线，评审确认定稿）
> 更新：2026-11-12
> 关联：00 索引、02 架构、03 数据库、04 API、05 实施计划、06 设计方案评审结果

## 1. 项目定位

构建一套高质量、通用、可复用的 Spring Boot 单体多模块脚手架，包含：

- 一个后端应用：Spring Boot 4.1.x、Java 25、Maven 多模块、DDD Lite。
- 管理端 Admin：Vue 3 + TypeScript + Vite + shadcn-vue。
- 门户 Portal：Vue 3 + TypeScript + Vite，初期仅骨架与公开 API 示例。

后端按业务领域划分模块，模块间零直接依赖；通过公共契约、端口与事件协作。初期单租户、无数据权限。

## 2. 目标与非目标

### 2.1 目标

- 提供可直接 fork 的工程骨架，新增业务模块只需增加依赖与包结构。
- 统一认证、RBAC、菜单权限、系统参数、日志审计的实现方式。
- 用 ArchUnit 固化模块与分层边界，避免 common 膨胀和跨模块穿透。
- 前后端契约由 OpenAPI 生成，减少手写漂移。
- 代码结构对人和 AI Agent 都足够直观。

### 2.2 非目标（明确不做）

- 多租户：本期不实现，业务表不预埋 `tenant_id`。
- 数据权限、ABAC、部门、岗位、数据范围。
- 微服务、CQRS、事件总线、分布式事务。
- CMS、文件管理、字典、工作流、消息中心、导入导出平台。
- 门户内容管理、C 端用户注册登录。
- App / 小程序客户端实现；仅预留 Bearer token 协议。
- 在线会话管理页面；仅提供强制下线接口。
- 通用 `Idempotency-Key` 机制。
- 全局逻辑删除：用户/角色用状态控制，菜单/配置删除仅通过 Flyway 迁移执行。
- 资源与系统参数的运行时创建/删除：由 Flyway 迁移维护，后台只更新展示属性或参数值。
- 仪表盘页面：本期不提供。
- 前端单元测试；前端仅做 Playwright 关键流程覆盖。

## 3. 角色与场景

| 角色 | 说明 | 主要场景 |
|---|---|---|
| 超级管理员 | 内置 `SUPER_ADMIN` 角色，绕过权限校验 | 初始化系统、全量管理 |
| 普通管理员 | 按角色授予的资源操作 | 用户、角色、菜单、参数、日志 |
| 门户访客 | 匿名 | 访问公开只读 API |
| App / 小程序用户 | 本期不实现 | 未来复用 token 协议 |

## 4. 功能需求

### 4.1 用户管理

**需求**

- 分页查询用户，支持用户名、状态筛选。
- 查看用户详情与已分配角色。
- 创建用户：用户名、初始密码、昵称、邮箱、手机号、角色；初始密码标记首次登录改密。
- 编辑用户资料；用户名作为登录标识，本期按不可修改设计（如需支持改名，需单独设计登录标识变更流程）。
- 禁用 / 启用用户；禁用时立即吊销该用户全部 token。
- 重置密码：管理员设置新密码，标记首次登录改密，并吊销全部 token。
- 分配角色：多角色，整体替换。
- 不提供物理删除。

**验收标准**

- 用户名唯一，重复创建返回 409。
- 禁用用户后，其现有 token 立即失效。
- 重置密码后，用户下次登录必须修改密码。
- 操作写入操作日志，登录行为写入登录日志。

### 4.2 登录认证与会话

**需求**

- 用户名 + 密码登录，密码使用 BCrypt。
- 连续 5 次失败锁定 15 分钟，错误提示统一，避免账号枚举。
- 使用 opaque token，Redis 只存 SHA-256 哈希。
- Web 端 token 放 `HttpOnly` / `Secure` / `SameSite=Lax` Cookie。
- App / 小程序协议预留：`Authorization: Bearer <token>`。
- 按设备单会话：同设备新登录踢旧 token，不同设备可同时在线。
- 超时：Web 空闲 30 分钟、绝对 12 小时；App 空闲 7 天、绝对 30 天，可配置。
- 提供按用户 / 设备强制下线接口。
- Cookie 模式启用 CSRF；Bearer 模式跳过。
- `/me` 返回用户、`superAdmin`、权限码、菜单树。

**验收标准**

- 登录成功后可访问受保护接口；无 token 返回 401。
- 同设备再次登录后，旧 token 返回 401。
- 强制下线后，目标 token 立即失效。
- 权限不足返回 403，不退出登录。
- 登录成功 / 失败 / 登出均写入登录日志。

### 4.3 RBAC

**需求**

- 统一资源树：目录、菜单、按钮、接口共用权限码。
- 资源类型包含 `DIRECTORY` / `MENU` / `BUTTON` / `API`；本期 `API` 为预留类型，接口鉴权复用菜单/按钮权限码。
- 角色与资源多对多，用户与角色多对多；角色扁平，不继承。
- 内置 `SUPER_ADMIN` 角色，不可删除、不可修改 code、不可禁用，持有者绕过权限校验。
- 权限码格式 `模块:资源:动作`。
- 权限按用户缓存于 Redis，角色 / 资源状态变更时失效。
- 角色被用户引用时禁止删除；资源有子节点或被授权时禁止删除（资源删除仅通过迁移执行）。
- 资源停用时若存在启用子资源，禁止停用。

**验收标准**

- 普通用户只能看到被授权资源对应的菜单与按钮。
- 角色授权变更后，用户下一次请求即生效。
- 超级管理员可访问全部菜单与接口。
- `SUPER_ADMIN` 不可禁用；删除受保护角色返回 409。
- 资源删除保护由迁移评审与完整性检查执行。
- 停用存在启用子资源的目录/菜单返回 409。

### 4.4 菜单与接口权限

**需求**

- 核心资源由 Flyway 预置，按 `code` 唯一；资源的新增与删除统一由 Flyway 迁移维护，后台不提供运行时创建/删除接口。
- 系统资源的 `type`、`code`、`path`、`component` 不可在后台修改。
- 后台可修改名称、父级、排序、图标、可见性、启停。
- 前端使用静态路由，后端菜单驱动侧边栏；新增页面必须“前端发版 + 新增迁移”。
- 前端启动时若菜单 `path` 无法匹配静态路由，输出警告。
- 本期不提供仪表盘页面；Admin 登录后默认跳转第一个有权限的菜单。

**验收标准**

- 后台修改菜单名称或排序后，刷新即生效。
- 尝试修改 `path` / `component` 被拒绝。
- 菜单路径与前端路由不一致时能尽早发现。
- Admin 登录后落到第一个有权限菜单；无仪表盘路由。

### 4.5 系统参数

**需求**

- 键值型运行参数，支持分组、描述、是否公开。
- 通过 `ConfigProvider` 端口读取，业务模块不直接依赖 `system` 模块。
- 不承担业务枚举；字典类需求不在本期范围。
- 系统参数由 Flyway 迁移维护，后台只更新参数值；不提供运行时创建/删除接口。
- 修改系统参数写入操作日志。
- 审计日志保留期、token TTL 等运行参数可配置。

**验收标准**

- 参数修改后，读取方在约定刷新周期内生效。
- 公开参数可通过 `/api/v1/public/**` 读取，私有参数仅管理端可见。
- 参数新增/删除仅通过迁移执行，管理端无对应入口。

### 4.6 操作日志与登录日志

**需求**

- 记录范围：增删改、状态变更、授权变更、登录 / 登出 / 登录失败；查询不记录。
- 登录日志同步写入；操作日志在事务提交后异步写入。
- 操作日志保留 180 天，登录日志保留 365 天，每日 02:00 分批清理，可配置。
- 参数脱敏、截断 2 KB；不记录密码、token、Cookie、响应体。
- 提供分页查询接口，不提供修改与删除。

**验收标准**

- 事务回滚时不产生操作日志。
- 登录失败记录失败原因。
- 清理任务按保留期删除，单批 1000 条。
- 日志中不出现敏感信息。

### 4.7 门户公开 API

**需求**

- 匿名访问，仅只读接口。
- 初期提供一个公开配置或示例查询接口，验证 `/api/v1/public/**` 路径与安全配置。
- 不建立 C 端用户体系。
- Portal 前端仅提供工程骨架与调用示例。

**验收标准**

- 未登录可访问公开接口。
- 公开接口不能访问管理端数据。
- Portal 能构建并调用公开接口。

## 5. 功能模块划分

### 5.1 Maven 模块

| 模块 | 职责 |
|---|---|
| `keel-bootstrap` | 启动、装配、全局配置、ArchUnit 测试 |
| `keel-iam` | 用户、登录会话、角色、资源、菜单、授权 |
| `keel-system` | 系统参数 |
| `keel-audit` | 操作日志、登录日志 |
| `keel-common-core` | 统一返回、错误码、异常、跨模块契约 |
| `keel-common-web` | 全局异常处理、参数校验、Web 约定 |
| `keel-common-security` | Security 配置、token、当前用户、鉴权 |
| `keel-common-persistence` | 持久层配置、基础实体、通用拦截器 |
| `keel-common-test` | 测试基座（test scope） |

### 5.2 依赖规则

- 业务模块之间零直接依赖。
- 业务模块只依赖 `common-*`。
- `common-*` 不得依赖业务模块。
- 跨模块协作通过 `common-core` / `common-security` 中的端口与事件契约。
- 模块内部按需分层：`interfaces`、`application`、`domain`、`infrastructure`；简单 CRUD 可省略领域层。
- 对象模型：PO 在 `infrastructure/persistence`，DTO/VO 使用 record，领域实体仅复杂业务使用。

### 5.3 模块内部职责

- Controller 只做参数接收、校验、调用应用服务、返回 VO。
- Application Service 负责用例编排与事务边界。
- Domain 负责复杂业务规则；简单 CRUD 不强行建领域服务。
- Repository / Mapper 只在 Infrastructure 出现。
- 跨模块 DTO 不暴露内部 PO / 领域对象。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | BCrypt、CSRF、token 哈希存储、统一错误提示、敏感信息脱敏、最小权限 |
| 性能 | 登录与简单分页查询在常规负载下 p95 ≤ 500ms（实施阶段以基准测试校准） |
| 扩展 | 无本地会话状态；token / 权限 / 锁计数存 Redis，可水平扩展 |
| 可维护 | ArchUnit 强制模块与分层边界；模块职责单一；文档与实现一致 |
| 可观测 | `X-Request-Id` 贯穿请求与日志；结构化日志；登录 / 操作日志可查询 |
| 兼容 | Spring Boot 4.1.x、Java 25；关键依赖版本在 Phase 1A 验证 |
| 测试 | 后端 JUnit 5 + Testcontainers + ArchUnit；前端 Playwright 关键流程 |
| 数据 | MySQL 8；Flyway 版本化迁移；本地时区 Asia/Shanghai |

## 7. 整体验收标准

- 9 个 Maven 模块可按依赖顺序构建通过。
- 登录、`/me`、用户分页、RBAC 授权、菜单渲染、日志查询可用。
- 超级管理员可完成全量管理；普通管理员受权限约束。
- 禁用用户、强制下线、权限变更即时生效。
- ArchUnit 规则全部通过。
- Playwright 覆盖登录、401/403、用户 CRUD、角色授权关键路径。
- 同域部署下 `/admin`、`/portal`、`/api/v1` 可访问。
- 设计文档 01–04 与实际实现一致；05 实施计划、06 评审记录同步更新。

## 8. 开放问题与风险

### 开放问题

原开放问题已在设计评审中关闭：

| # | 原问题 | 结论 | 依据 |
|---|---|---|---|
| 1 | Portal 是否复用 shadcn-vue 设计语言 | 复用，与 Admin 保持同一设计语言 | 02 §7.3、00 当前决策基线 |
| 2 | 错误码清单与核心资源清单的最终版本 | 已定稿 | 04 §11、03 §9.2 |
| 3 | 用户名是否允许修改 | 本期不可修改 | 01 §4.1、04 §5.4 |
| 4 | 系统参数缓存策略与刷新周期 | Redis 缓存，TTL 30 分钟，更新后立即失效 | 02 §5 |
| 5 | 多实例日志清理是否加锁 | 单实例不加锁；多实例前引入 ShedLock 或等价锁 | 02 §10、05 §13 |

本轮评审新增事项已全部确认：

| 事项 | 结论 |
|---|---|
| 资源与系统参数生命周期 | 迁移维护；后台不提供创建/删除接口 |
| 仪表盘菜单 | 不提供；Admin 登录后跳转第一个有权限菜单 |
| `SUPER_ADMIN` | 不可删除、不可修改 code、不可禁用 |
| `API` 资源类型 | 预留类型，不种子化；接口鉴权复用菜单/按钮权限码 |
| 停用目录/菜单 | 存在启用子资源时拒绝停用并返回 409 |

### 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 本地时区存储 | 未来多地域迁移成本高 | 统一 JVM / MySQL / JDBC 时区，文档明确单时区假设 |
| 自增 ID 可枚举 | 公开接口暴露数据量 | 管理端接受；公开 API 使用外部标识 |
| 仅 Playwright | 缺少组件级快速反馈 | 控制 E2E 范围，核心组件改动频繁时补 Vitest |
| shadcn-vue 源码复制 | 组件升级需人工维护 | 记录版本，定制集中在 `components/app` |
| 不设独立 spike | 兼容性问题在 Phase 1 暴露 | Phase 1A 设置验证门与回退预案 |
| 静态路由与菜单漂移 | 菜单指向不存在的页面 | 前端启动校验 + 发版与迁移成对执行 |
