## 阅读顺序

`01 → 02 → 03 → 04 → 05 → 06`

- 01 定义“做什么”和“不做什么”。
- 02 定义“怎么组织”和“为什么这样选”。
- 编写 03 前先阅读 `../rules/database-rules.md`。
- 编写 04 前先阅读 `../rules/api-rules.md`。
- 03 把领域模型落到表结构。
- 04 把用例落到接口契约。
- 05 把决策落到实施顺序与验收门。

## 文档约定

- 单一事实来源：同一决策只在一份文档中详细描述，其他文档引用编号。
- 决策变更先改文档，再改代码；代码与文档不一致视为缺陷。
- 版本号采用 `v0.x`，进入实施后按里程碑递增。
- 术语以 01 文档末尾的术语表为准。
- 所有示例中的路径、字段、错误码必须与 03 / 04 文档一致。
- `docs/rules/` 下的规范文档是设计评审的强制依据。

## 当前决策基线

| 领域 | 结论 |
|---|---|
| 运行时 | Java 25 LTS、Spring Boot 4.1.x |
| 构建 | Maven 单体多模块，9 个模块；groupId `io.github.keel`，版本 `1.0.0` |
| 持久层 | MySQL 8、MyBatis-Plus 3.5.15+、Flyway |
| 认证 | Spring Security 7 无状态 + opaque token + Redis |
| 权限 | 统一资源树、RBAC、`SUPER_ADMIN` 内置角色 |
| 资源/参数 | Flyway 迁移维护；后台只更新，不提供创建/删除 |
| 内置角色 | `SUPER_ADMIN` 不可删除、不可改 code、不可禁用 |
| 资源类型 | `DIRECTORY` / `MENU` / `BUTTON` / `API`；`API` 预留，不种子化 |
| Admin 落地页 | 不提供仪表盘，登录后跳转第一个有权限菜单 |
| 前端 | Admin / Portal 位于 `frontend/` 子目录；Vue 3 + TypeScript + Vite |
| Admin UI | shadcn-vue + Tailwind CSS v4 + VeeValidate/Zod |
| Portal UI | shadcn-vue + Tailwind，与 Admin 同一设计语言 |
| 运维 | Actuator 仅暴露 `/actuator/health` |
| 缓存 | Redis：权限缓存、系统参数缓存 |
| CI | 暂不绑定平台，使用平台无关命令与阶段 |
| 部署 | 同域 `/admin`、`/portal`、`/api/v1` |
| 测试 | JUnit 5 + Testcontainers + ArchUnit；前端仅 Playwright |
